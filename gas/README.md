# 工程表生成（Google Apps Script版）

入居者一覧をGoogleスプレッドシートで管理している場合、Apps Scriptで工程表を自動生成できます。

## 導入手順

1. 入居者一覧のGoogleスプレッドシートを開く
   （xlsファイルをGoogleドライブにアップロードし、Googleスプレッドシート形式に変換しておく）
2. メニュー「拡張機能」→「Apps Script」を開く
3. `GenerateKoujiSchedule.gs` の内容をコピーしてエディタに貼り付け、保存する
4. スプレッドシートのタブを再読み込み（リロード）する
   - 「工程表」というメニューが追加されます
5. 「工程表」→「工程表を作成」を実行する
   - 初回実行時はGoogleアカウントへの権限承認が必要です
6. 「工程表」という名前のシートが作成・更新されます

## 複数の建物で繰り返し使う場合

建物ごとにApps Scriptのコードを毎回貼り付け直すのは手間がかかります。一度正しく
動作するスプレッドシートができたら、それを「テンプレート」としてコピーして使い回すのが
おすすめです。

1. 正しく動作しているスプレッドシート（入居者一覧・スクリプト貼り付け済み）を
   テンプレートとして保管しておく
2. 新しい建物で使う際は、テンプレートを開き「ファイル」→「コピーを作成」を選ぶ
   - コピーされた新しいスプレッドシートには、Apps Scriptのコードもそのまま
     引き継がれるため、貼り付け直しは不要
3. コピー後のスプレッドシートで、A1（物件名）・入居者一覧の部屋番号を新しい建物の
   ものに書き換える
4. テンプレート自体のコードを更新したい場合（今後の機能追加など）は、テンプレート側に
   1回貼り直せば、それ以降にコピーする建物にはすべて最新版が反映される
5. 複数建物のデータを1か所に集約したい場合は、テンプレート側の「設定」シートに
   マザースプレッドシートのURLをあらかじめ入力しておくと、それ以降にコピーする建物には
   その設定も引き継がれる（詳細は後述の「マザースプレッドシートへのデータ集約」を参照）

## 初回セットアップの一括実行

新しい建物で使い始める際、「回答フォームを作成する」→「各住戸QRコードを作成する」→
「住戸QRコード一覧表を作成する（社内用）」を1つずつ実行する代わりに、
「工程表」→「★初期セットアップを一括実行」を実行すると、この3つがまとめて
順番に実行されます（各ステップの完了ダイアログはそのまま表示されるので、
OKを押して次に進んでください）。事前に入居者一覧へ部屋番号を入力しておく必要があります。

## 入居者一覧のフォーマット

各シートとも以下の形式（Excel版と同じ）です。

- 1行目: A1に物件名
- 2行目: 見出し（部屋番号, 氏名, 電話, 携帯, 日程, 備考, ...）
- 3行目以降: データ
  - A列: 部屋番号
  - B列: 氏名（「空室」の場合は空室として表示）
  - E列: 日程（工程表の作成に使う「確定日程」。例: `6/19（金）13:00`, `3月28日(土)9：00`）
  - F列: 備考（「工期外希望」「カメラ付」「受話器」に対応）
  - G列: 確認コード、H・I・J列: 第1〜第3希望（オンライン回答フォーム利用時に自動入力される。後述）
  - K列: 所有者メール（任意。住戸に居住していない所有者向け。後述）

**入力ガイドについて**：1行目・2行目が空欄の場合、いずれかのメニュー項目を一度実行すると、
A1に「物件名を入力してください」というメモ（セルの右上に表示される注釈）が、
2行目のA〜F列には見出し文字列（部屋番号・氏名・電話・携帯・日程・備考）が自動で入ります。
これは「部屋番号を誤って1〜2行目に直接入力してしまい、3行目以降しかデータとして
認識されない」という事故を防ぐためのものです。既に値が入っているセルは上書きされません。

## 印刷（PDF出力）について

Apps Scriptからは用紙サイズ・1ページ収まり設定はできないため、作成後に
「ファイル」→「印刷」で 用紙サイズ:A4・向き:横・拡大縮小:このシートを1ページに
収める を選択してPDF出力してください。

## オンライン回答フォーム（紙アンケート＋ポスト回収の代替）

住民に紙のアンケートを配って現地のポストから回収する代わりに、QRコードから
Googleフォームで直接回答してもらう方法です。工事希望日時は第1〜第3希望まで
集められます。回答は自動的に入居者一覧に反映されるため、ポストへの回収訪問や
手書きのExcel転記が不要になります。

### 導入手順

1. 入居者一覧シートに 部屋番号 を入力しておく（氏名・電話・日程・備考は空欄でよい。
   これらは住民自身がフォーム上で入力します）
   - 空室の行はB列に「空室」と入力しておくと、フォームの部屋番号選択肢から除外されます
2. スプレッドシートのタブを再読み込みし、「工程表」メニューから
   「回答フォームを作成する」を実行する
   - 初回実行時はGoogleアカウントへの権限承認が必要です
   - 入居者一覧の部屋番号を選択肢にしたGoogleフォームが自動作成され、
     このスプレッドシートに接続されます（「フォームの回答 1」シートが追加されます）
   - 実行後のダイアログにフォームURLが表示されます
3. 続けて「工程表」メニューから「各住戸QRコードを作成する」を実行する
   - 入居者一覧の各部屋（空室を除く）に4桁の「確認コード」（G列）が自動発行されます
   - 部屋番号＋確認コードを埋め込んだ回答リンクを1住戸1ページのQRコードにした
     Googleスライドが生成されます（実行後のダイアログにスライドURLが表示されます）
   - 各ページ右側の部屋番号見出し（「101号室」等）は縦書き風（1文字ずつ改行して
     縦に並べる形）で表示されます（Slides APIには本物の縦書き設定が無いための代替表現です）
   - 案内文には「設定」シートの問い合わせ先（表示名・電話番号）を使った、
     お電話でのご案内を希望する場合の連絡先も自動で記載されます（スマホを持っていない・
     操作が難しい住民の方も、この印刷物だけで電話案内に進めます）
4. スライドを印刷し、1ページずつ切り分けて該当する住戸のポストや玄関先に
   個別に配布・掲示する（スマホを使わない住民向けに、従来の紙アンケートも並行して残せます）
5. 住民がQRコードを読み取り、氏名・電話番号・工事希望日時（第1希望は必須、
   第2・第3希望は任意）を入力して回答すると、部屋番号と確認コードの組み合わせが
   一致した場合のみ、自動的に入居者一覧の該当する部屋番号のB列（氏名）・
   C列（電話）・E列（確定日程＝既定では第1希望）・F列（備考）・
   H〜J列（第1〜第3希望）が更新されます
6. 第1希望のとおりに施工できない部屋があれば、H〜J列（第1〜第3希望）を見ながら
   E列を手動でその部屋の第2希望または第3希望に書き換える
7. 「工程表」→「工程表を作成」を実行すると、E列の内容を反映した工程表が生成されます
   （未回答の部屋は従来どおり「未提出」として一覧表示されます）

### 住戸QRコード一覧表（社内用）

配布・回収状況の管理や、印刷したQRコードと部屋番号の突き合わせ用に、
全住戸の「部屋番号・確認コード・QRコード」を1枚の一覧表にまとめられます。

- 「工程表」→「住戸QRコード一覧表を作成する（社内用）」を実行すると、
  「QR一覧（社内用）」シートに部屋番号・確認コード・QRコード（縮小画像）・
  配布チェック欄（チェックボックス）の一覧が作成されます
- **この一覧表には全住戸の確認コードが1か所にまとまっているため、
  住民への配布物には使わず、社内で厳重に管理してください**
  （住民に配布するのは、あくまで「各住戸QRコードを作成する」で作成する
  1住戸1ページのスライドです）
- 部屋番号を追加・変更した場合は、再度実行するとシートが作り直されます
- 「回答用URL」列にはHYPERLINK式が入っています。お電話で希望日時を伺い、
  代わりにフォームへ入力する（高齢者の方などからの電話代行対応）場合は、
  このリンクをクリックして該当住戸のフォームを開いてください

### 高齢者・スマートフォンを使わない方への対応

- フォームの説明文には、操作でお困りの場合の問い合わせ先（`CONTACT_PHONE`定数）が
  表示されます。実際の連絡先に書き換えて使用してください
- お電話で希望日時を伺った場合は、上記「住戸QRコード一覧表」の「回答用URL」列から
  該当住戸のフォームを開き、管理者が代わりに入力できます
- 紙のアンケート用紙（大きめ文字）も従来どおり併用できます

### 住戸に居住していない所有者（賃貸オーナー等）への対応

賃貸に出している住戸など、実際にお住まいでない所有者にもオンラインで
回答依頼を送れます。

1. 入居者一覧のK列「所有者メール（任意）」に、対象住戸の所有者のメールアドレスを入力する
   （居住者がいる住戸は、通常は居住者にQRコードで回答してもらえば足り、
   この列への入力は不要です）
2. 「工程表」→「所有者へ回答リンクをメールで送る」を実行する
   - K列にメールアドレスが入力されている住戸にのみ、その住戸専用の回答リンクを
     記載したメールが送信されます（部屋番号・確認コードが埋め込まれており、
     他住戸の回答には使えません）
   - メール本文の電話番号はタップでそのまま発信できるリンクになっています
3. 所有者がメール内のリンクから回答すると、通常のQRコード回答と同様に
   入居者一覧に反映されます

### 「設定」シート（回答期限・問い合わせ先）

回答期限や問い合わせ先を、コードを直接編集せずスプレッドシート上で管理できます。
「回答フォームを作成する」を初めて実行すると「設定」シートが自動作成されます
（すでにある場合は上書きされません）。

| 設定項目 | 内容 |
|---|---|
| 回答期限 | 例: `2026/08/10`。空欄の場合は期限なし扱い |
| 問い合わせ先（表示名） | 例: `施工会社`（既定値） |
| 問い合わせ先電話番号 | 例: `052-269-9100`（既定値） |
| 担当者通知メール（任意） | 日程重複が発生した際に通知を受け取るメールアドレス。空欄なら通知メールは送られない |
| マザースプレッドシートのURL（任意） | 複数建物のデータを集約するスプレッドシートのURL。空欄なら集約は行われない（詳細は後述） |

この値を入力・変更してから「回答フォームを作成する」をもう一度実行すると、
以下に自動で反映されます。

- Googleフォームの説明文（回答期限・問い合わせ先）
- 所有者宛メール（回答期限・問い合わせ先、電話番号はタップで発信できるリンク）
- 「未回答状況レポートを表示」の表示内容

さらに、回答期限を過ぎると、日次トリガー（`closeFormIfDeadlinePassed`）により
**Googleフォーム自体が自動的に新規回答の受付を停止**します（期限日の23:59まで受付）。
このトリガーは「回答フォームを作成する」の実行時に、まだ無ければ自動で登録されます。

「工程表」→「未回答状況レポートを表示」を実行すると、回答期限までの残り日数
（または超過日数）と、未回答の部屋番号一覧をその場で確認できます。

### 日程の重複チェック（予定がダブった場合の動き）

複数の部屋が同じ日時（E列＝確定日程）を選んでしまうことがあります
（例: 101号室・102号室がどちらも「第1希望」で同じ日の同じ時間を選んだ場合）。
このシステムは日時を自動で調整・振り分けたりはしません。代わりに重複を検知して
気づけるようにする仕組みが入っています。

- 住民の回答が入居者一覧に反映されるたび（フォーム回答・電話代行入力とも）に、
  全シートを横断して日程の重複が自動チェックされます
- 重複している部屋があれば、該当する入居者一覧のE列のセルが**ピンク色**で
  強調表示され、セルのメモに重複している部屋番号が記載されます
- 「設定」シートの「担当者通知メール」にアドレスを入力しておくと、重複が発生する
  たびにそのアドレス宛にメールで通知が届きます（空欄の場合はメール通知はされず、
  シート上の色付けのみで確認する運用になります）
- 「工程表」→「日程重複チェックを表示」を実行すると、いつでも現在の重複状況を
  一覧で確認できます（入居者一覧を手動編集した場合の再チェックにも使えます）
- 重複が見つかったら、いずれかの部屋のH〜J列（第1〜第3希望）を見ながら、
  E列を空いている希望日時に手動で書き換えてください。次回のチェック時に
  自動的に色付け・メモが解除されます
- 「工程表を作成」の実行時にも自動でこのチェックが行われます（生成される
  工程表自体は重複があってもそのまま出力されるため、事前にこの重複チェックで
  解消しておくことを推奨します）

### マザースプレッドシートへのデータ集約（複数建物を横断して閲覧したい場合）

建物ごとにスプレッドシートを分けて運用しつつ、全建物の状況を1か所（マザー
スプレッドシート）でまとめて閲覧したい場合の仕組みです。

#### 準備

1. 集約用の**空のGoogleスプレッドシートを1つ新規作成**する（シート名は自由。
   Apps Scriptのコードを貼り付ける必要はありません）
2. そのスプレッドシートのURLをコピーする
3. 集約したい各建物のスプレッドシートを開き、「設定」シートの
   「マザースプレッドシートのURL（任意）」に、そのURLを貼り付ける
   （テンプレートを複製して建物を増やす場合は、テンプレート側に1回入力しておけば
   複製先すべてに引き継がれます）

#### 同期のタイミング

- 住民の回答が入居者一覧に反映されるたびに自動で同期されます
- 「★初期セットアップを一括実行」実行時にも同期されます
- 「工程表」→「マザーデータへ同期する」で、いつでも手動で同期できます
  （入居者一覧を手動編集した後の反映にも使えます）

#### 集約される内容

マザースプレッドシート側に自動で作成される「集約データ（マザーシート）」シートに、
建物ごとの部屋番号・氏名・電話・携帯・確定日程・備考・第1〜第3希望・最終更新日時が
一覧になります。同じ建物を再同期すると、その建物の行は洗い替え（削除して書き直し）
されるため、重複は発生しません。

**確認コード（住戸QRコードの合言葉）はマザースプレッドシートには一切書き込まれません**
（複数建物分の確認コードが1か所に集まるセキュリティリスクを避けるためです）。

### 住戸専用QRコード（パスワード付き）の仕組み

- 各QRコードには、その住戸の部屋番号と確認コード（4桁）の両方があらかじめ
  埋め込まれています。住民は基本的に何も入力せず送信するだけで回答できます
- 他の住戸のQRコードを使って別の部屋番号で回答しようとしても、確認コードが
  一致しないため入居者一覧には反映されません。この場合は「フォーム取込エラー」
  シートに記録されます（誰が・いつ・どの部屋で不一致になったかを確認できます）
- 確認コードは入居者一覧のG列に保存されています。個別に配布する紙を紛失した場合の
  再発行や、コードを直接伝える手段としても利用できます

### 補足

- 部屋番号を入居者一覧に追加・変更した場合は、もう一度
  「回答フォームを作成する」→「各住戸QRコードを作成する」の順に実行してください
  （フォームの質問はできる限り再利用され、既存の質問のIDは変わらないため、
  配布済みのQRコードは無効になりません。新しく追加された部屋の分だけQRコードを
  追加で印刷・配布してください）
- フォームのタイトル・説明文は、入居者一覧のA1（物件名）や「設定」シートの内容を基に
  「回答フォームを作成する」の実行ごとに更新されます。A1を後から書き換えた場合も、
  もう一度実行すれば既存フォームのタイトルに反映されます
- 何らかの理由で自動反映が行われなかった場合は、「フォーム回答を再取り込み」を
  実行すると、フォームの全回答を入居者一覧に取り込み直せます
  （このとき確認コードの照合も行われるため、不一致の回答は引き続き反映されません）
- 同じ部屋番号・確認コードの組み合わせで複数回回答された場合は、
  最後に反映した内容で上書きされます
- QRコード画像の生成には外部サービス（api.qrserver.com、失敗時はquickchart.ioに
  自動フォールバック）を利用しています。両方とも失敗した場合は、該当ページに
  回答用URLが代わりに表示されるので、そのURLを他のQR作成サイトなどでQRコード化してください
- 回答フォームが「ドメイン内のユーザーのみ」に制限されている場合、住民が
  ログインなしで回答できるよう、Googleフォームの設定画面（右上の歯車アイコン）で
  該当の制限を解除してください
